# AI-PM Plan 2.5 — AgentScope 技术验证（关卡）

> **Prerequisite:** Plan 2 任务系统完成（Agent 需要读写任务数据进行验证）
> **Goal:** 确认 AgentScope 框架在真实场景下满足项目需求。验证不通过则重新评估 AI 引擎方案。

**Duration:** 1-2 周（5-10 个工作日）

**定位：** Plan 3 AI 引擎开发的 **P0 前置关卡**。必须在 Plan 3 启动前通过全部 5 项验证。

---

## 背景

Plan 3 AI 引擎将使用 AgentScope 作为 Agent 框架（设计规范 §6）。AgentScope 提供：

- **ReActAgent 编排** — Thought → Action → Observation 循环
- **MCP 协议兼容工具系统** — 工具注册和调用
- **沙箱执行** — 代码安全执行环境
- **A2A 通信** — Agent 间消息传递
- **AutoContextMemory** — Agent 上下文记忆

Plan 2.5 的目标是验证这些能力在本地 LLM（DeepSeek/Qwen）+ FastAPI 协作模式下 **稳定可用**。

---

## 验证项

### V1: ReActAgent 工具调用稳定性

| 维度 | 说明 |
|------|------|
| **目标** | 确认 AgentScope ReActAgent 在连续调用中正确执行 Thought→Action→Observation 循环 |
| **成功标准** | 连续 50 次工具调用零异常（无循环卡死、无工具选择错误） |
| **方法** | 编写自动化循环测试脚本：创建 ReActAgent → 分配模拟任务 → 验证工具调用链路 → 记录每次执行日志 |
| **关键检查点** |
| 1. Agent 是否正确解析任务意图并选择正确工具 |
| 2. 工具调用参数格式是否正确 |
| 3. 达到 max_iters 时是否正确终止（不卡死） |
| 4. 连续 50 次执行中无内存泄漏（监控 Python 进程内存） |
| **风险** | AgentScope 的 ReActAgent 可能在本地 LLM（非 GPT-4）下工具选择准确率下降 |

### V2: Webhook 回调可靠性

| 维度 | 说明 |
|------|------|
| **目标** | 确认 AgentScope → FastAPI Webhook 回调链路可靠 |
| **成功标准** | 回调延迟 < 3s，成功率 > 99%（100 次中至少 99 次成功） |
| **方法** | 压力测试：AgentScope 执行模拟任务 → 完成后通过 Webhook 回调 FastAPI → FastAPI 记录回调时间和成功率 |
| **关键检查点** |
| 1. Webhook 是否在 Agent 完成后 3s 内触发 |
| 2. 回调 payload 格式是否完整（output, thinking_log, tokens_used, duration_ms） |
| 3. FastAPI 接收端是否正确解析和持久化 |
| 4. 网络断开时是否重试（至少 3 次） |
| **风险** | AgentScope Webhook 机制可能针对云端设计，本地部署需要额外配置 |

### V3: Memory 摘要质量

| 维度 | 说明 |
|------|------|
| **目标** | 确认 AI 助生成的记忆摘要质量可接受 |
| **成功标准** | 人工评分 ≥ 3/5（5 分制，3 分 = "基本可用，需少量修改"） |
| **方法** | 准备 10 个真实场景的任务完成记录 → AI 助生成 2 级摘要（~50 tokens + ~200 tokens）→ 3 人盲评打分 |
| **关键检查点** |
| 1. 摘要是否保留关键信息（谁、做了什么、为什么） |
| 2. 一句话（~50 tokens）是否足够概括 |
| 3. 段落（~200 tokens）是否覆盖关键上下文 |
| 4. 是否有幻觉（编造不存在的信息） |
| **风险** | 本地 LLM 的摘要能力可能显著弱于 GPT-4，MVP 可能需要调整摘要策略 |

### V4: AgentScope + FastAPI 集成

| 维度 | 说明 |
|------|------|
| **目标** | 确认 AgentScope 与 FastAPI 的三种协作模式均可用 |
| **成功标准** | 同步 RTT < 5s，异步任务正常启动和回调，Webhook 回调正常 |
| **方法** | 端到端集成测试：FastAPI 创建 Agent 任务 → AgentScope 执行 → Webhook 回调 → FastAPI 写入 Review 队列 |
| **关键检查点** |
| 1. 同步调用（简单查询）：FastAPI → AgentScope → 返回，RTT < 5s |
| 2. 异步调用（长任务）：FastAPI 创建任务后立即返回 execution_id，后台执行 |
| 3. SSE 流式日志：Work-in-Public 日志流正常推送到前端 |
| 4. AgentScope 进程生命周期管理（启动/健康检查/优雅关闭） |
| **风险** | AgentScope 作为独立进程运行，进程间通信可能引入额外延迟 |

### V5: 本地 LLM 兼容性

| 维度 | 说明 |
|------|------|
| **目标** | 确认 AgentScope 可正常使用 DeepSeek/Qwen 等本地部署模型 |
| **成功标准** | DeepSeek-V3 和 Qwen2.5-72B 均可正常跑通 V1-V4 验证 |
| **方法** | 切换 LLM 后端（DeepSeek → Qwen），重新运行 V1 和 V2 测试 |
| **关键检查点** |
| 1. OpenAI 兼容 API 格式是否被 AgentScope 正确适配 |
| 2. 不同模型的 tool calling 格式是否兼容 |
| 3. 不同模型的输出格式差异是否影响 Agent 解析 |
| **风险** | 不同模型的 tool calling / function calling 格式有差异，可能需要适配层 |

```bash

- Python 3.11+
- FastAPI 开发服务器（本地 8000 端口）
```

## 备选方案

如果 AgentScope 验证不通过：

| 备选 | 说明 | 影响 |
|------|------|------|
| A: LangGraph | Python 生态最成熟的 Agent 框架，StateGraph 模式稳定 | Plan 3 架构重写（但已有初版），工具系统需自建 |
| B: 自建 Agent 编排 | 基于 asyncio + LLM 直调，最轻量 | 丢失 AgentScope 的 ReAct 模式、记忆、沙箱等能力 |
| C: 降级为 API 直调 | 不用 Agent 框架，FastAPI 直接调用 LLM API | AI 能力降级为简单的提示词问答，失去多步推理能力 |

**推荐备选：A > B > C**
