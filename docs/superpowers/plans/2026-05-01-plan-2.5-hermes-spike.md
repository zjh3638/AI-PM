# AI-PM Plan 2.5 — Hermes Agent 技术验证（关卡）

> **Prerequisite:** Plan 2 任务系统完成（Agent 需要读写任务数据进行验证）
> **Goal:** 确认 Hermes Agent 在内网环境下满足项目需求。验证不通过则重新评估 AI 引擎方案。

**Duration:** 1-2 周（5-10 个工作日）

**定位：** Plan 3 AI 引擎开发的 **P0 前置关卡**。必须在 Plan 3 启动前通过全部 5 项验证。

---

## 背景

Plan 3 AI 引擎将使用 Hermes Agent（Nous Research）作为 Agent 框架（设计规范 §6）。Hermes 提供：

- **Self-Improving Learning Loop** — Agent 从成功/失败执行中自动生成和优化 Skill 文件（`~/.hermes/skills/`），复杂任务（5+ 次工具调用、错误恢复、人类修正）后自动触发
- **四层记忆系统** — MEMORY.md（持久的 Prompt Memory）+ Session Archive（SQLite+FTS5）+ Skill 文件 + Honcho（可选，跨会话用户建模）
- **MCP 协议兼容工具系统** — 工具注册和调用，支持 OpenAI/Anthropic function calling 格式
- **多模型网关** — 20+ 模型提供商支持，包括 Ollama 本地模型、OpenAI 兼容接口
- **Periodic Self-Refinement** — 空闲时自动回顾近期操作并决定需要持久化的记忆

Plan 2.5 的目标是验证这些能力在内网本地 LLM（DeepSeek/Qwen）+ FastAPI 协作模式下 **稳定可用**。

---

## 验证项

### V1: Skill 文件生成与自学习闭环稳定性

| 维度 | 说明 |
|------|------|
| **目标** | 确认 Hermes 的 Self-Improving Learning Loop 能够从复杂任务中稳定生成 Skill 文件 |
| **成功标准** | 连续 20 次复杂任务（5+ 工具调用）执行零异常，且生成的 Skill 文件在第 2 次同类任务时能正确被复用 |
| **方法** | 编写自动化循环测试脚本：创建 Hermes Agent 任务 → 分配同一类复杂任务 10 次 → 验证后续任务的 Skill 是否复用并提升效率 |
| **关键检查点** |
| 1. Hermes 是否在复杂任务完成后正确触发 Skill 生成 |
| 2. 生成的 Skill 文件内容是否准确（无幻觉、无错误操作序列） |
| 3. 第 2-10 次同类任务是否自动加载并应用已生成的 Skill |
| 4. Skill 修正（用户打回后）是否正确 patch 而非覆盖 |
| 5. 连续 20 次执行中无内存泄漏（监控 Hermes 进程内存） |
| **风险** | Hermes 的 Skill 自学习机制可能在本地 LLM（非 Claude/GPT-4）下生成质量显著下降；Skill 格式遵循 agentskills.io 标准，需确认与自定义工具的兼容性 |

### V2: Hermes API 与 Webhook 回调可靠性

| 维度 | 说明 |
|------|------|
| **目标** | 确认 Hermes → FastAPI Webhook 回调链路可靠，API 同步调用稳定 |
| **成功标准** | API 调用 RTT < 5s，Webhook 回调延迟 < 3s，成功率 > 99%（100 次中至少 99 次成功） |
| **方法** | 压力测试：Hermes 执行模拟任务 → 完成后通过 Webhook 回调 FastAPI → FastAPI 记录回调时间和成功率；同时测试 API 同步调用响应时间 |
| **关键检查点** |
| 1. Hermes HTTP API 是否可用，同步查询 RTT < 5s |
| 2. Webhook 是否在 Agent 完成后 3s 内触发 |
| 3. 回调 payload 格式是否完整（output、reasoning_log、tokens_used、duration_ms、skill_updated） |
| 4. FastAPI 接收端是否正确解析和持久化 |
| 5. 网络断开时是否重试（至少 3 次） |
| **风险** | Hermes 的 Webhook 机制默认设计用于在线环境，内网部署需要确认 Webhook 端点配置和网络可达性；降级方案为 FastAPI 定时轮询 Hermes 任务状态 |

### V3: Memory 召回准确率与 Skill 质量

| 维度 | 说明 |
|------|------|
| **目标** | 确认 Hermes 内置记忆系统（MEMORY.md + Session Archive）的召回准确率和 Skill 文件质量可接受 |
| **成功标准** | Memory 召回人工评分 ≥ 3/5，Skill 质量人工评分 ≥ 3/5（5 分制，3 分 = "基本可用，需少量修改"） |
| **方法** | （1）Mock 10 组项目上下文写入 MEMORY.md，发起 10 次需要上下文的任务，检查 Hermes 是否正确检索和引用；（2）准备 10 个真实场景的任务执行记录 → Hermes 生成 Skill 文件 → 3 人盲评打分 |
| **关键检查点** |
| 1. MEMORY.md 中的关键信息是否被 Agent 正确加载和引用 |
| 2. Session Archive (SQLite+FTS5) 的历史检索是否正确返回相关记录 |
| 3. Skill 文件是否保留了关键操作步骤，无遗漏/幻觉 |
| 4. 长期积累后 MEMORY.md 是否保持在 ~3,575 字符限制内（Hermes 截断机制） |
| **风险** | Hermes 的记忆系统假设云端模型能力，本地 LLM 可能在摘要和检索质量上不及预期；MEMORY.md 需考虑与自定义 OpenSpec 的分工 |

### V4: Hermes + FastAPI 集成

| 维度 | 说明 |
|------|------|
| **目标** | 确认 Hermes 与 FastAPI 的三种协作模式均可用（独立进程 + HTTP API） |
| **成功标准** | 同步 RTT < 5s，异步任务正常启动和回调，Docker Compose 编排下运行稳定 |
| **方法** | 端到端集成测试：FastAPI 创建 Agent 任务 → Hermes 执行 → Webhook 回调 → FastAPI 写入 Review 队列 |
| **关键检查点** |
| 1. 同步调用（简单查询）：FastAPI → Hermes API → 返回，RTT < 5s |
| 2. 异步调用（长任务）：FastAPI 创建任务后立即返回 execution_id，后台执行 |
| 3. 任务状态轮询：Fallback 模式下 FastAPI 定时查询 Hermes 任务状态是否正常 |
| 4. Hermes 进程生命周期管理（Docker 容器启动/健康检查/优雅关闭） |
| 5. Docker Compose 编排下 FastAPI 和 Hermes 容器间网络通信正常 |
| **风险** | Hermes 作为独立进程/容器运行，跨容器 HTTP 通信引入延迟；Hermes 的 Docker 镜像需离线导入内网 |

### V5: 本地 LLM 兼容性（内网环境）

| 维度 | 说明 |
|------|------|
| **目标** | 确认 Hermes 可在内网环境下使用 DeepSeek/Qwen 等本地部署模型正常工作 |
| **成功标准** | DeepSeek-V3 和 Qwen2.5-72B 均可正常跑通 V1-V4 验证 |
| **方法** | 配置 Hermes 模型指向内网 LLM API（OpenAI 兼容格式），分别使用 DeepSeek 和 Qwen 重新运行 V1 和 V2 测试 |
| **关键检查点** |
| 1. Hermes 能否正确配置指向内网 OpenAI 兼容 API |
| 2. 不同模型的 tool calling / function calling 格式是否兼容 |
| 3. 本地模型的 tool calling 准确率是否显著低于云端模型 |
| 4. Hermes 内置的辅助模型（如图像分析、网页抓取）是否可指定为本地模型 |
| **风险** | Hermes 默认适配 20+ 云端模型，内网本地模型的 tool calling 能力可能不足；部分 Hermes 功能可能需要额外模型（如 Gemini Flash 做辅助任务）需确认可替换 |

## 工具和基础设施

### 验收环境

```bash
# 测试环境
- Python 3.11+
- Docker + Docker Compose
- FastAPI 开发服务器（容器，端口 8000）
- Hermes Agent 独立容器
- 内网 LLM API：DeepSeek-V3 / Qwen2.5-72B（OpenAI 兼容格式）

# Hermes 安装（外网下载 → 内网导入）
# 方式 1: 离线 Docker 镜像
docker pull nousresearch/hermes-agent:latest        # 外网
docker save nousresearch/hermes-agent:latest -o hermes-agent.tar
# → 导入内网
docker load -i hermes-agent.tar

# 方式 2: pip install（如 Hermes 提供 Python SDK）
pip install hermes-agent

# 配置内网模型
hermes setup
hermes model  # 选择 OpenAI Compatible，填入内网 LLM API 地址

# 测试脚本
server/tests/ai/
├── test_v1_skill_loop.py          # 20 次复杂任务 Skill 生成循环
├── test_v2_api_webhook.py         # 100 次 API+回调压力测试
├── test_v3_memory_skill_quality.py # 10 样本盲评准备
├── test_v4_integration.py         # FastAPI ↔ Hermes 端到端
└── test_v5_model_switch.py        # 模型切换测试
```

### 降级策略

开发期间如 Hermes 能力不足，保留以下降级路径：

1. **Skill 生成不稳定** → 禁用自学习功能，使用预置静态 Skill 文件 +
2. **Webhook 不可用** → 改用 FastAPI 轮询 Hermes 任务状态
3. **Hermes 内置记忆不足** → 降级为只使用 Hermes 执行引擎，记忆由自定义系统（设计规范 §7）接管
4. **完全不可用** → 切换备选方案（见下）

## 备选方案

如果 Hermes Agent 验证不通过：

| 备选 | 说明 | 影响 |
|------|------|------|
| A: LangGraph | Python 生态最成熟的 Agent 框架，StateGraph 模式稳定 | Plan 3 架构重写，工具系统需自建，记忆系统需完全自建 |
| B: 自建 Agent 编排 | 基于 asyncio + LLM 直调，最轻量 | 丢失 Hermes 的自学习、记忆、Skill 等能力，开发量最大 |
| C: 降级为 API 直调 | 不用 Agent 框架，FastAPI 直接调用 LLM API | AI 能力降级为简单的提示词问答，失去多步推理和自学习能力 |

**推荐备选：A > B > C**
